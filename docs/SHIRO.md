# 自動原音設定

`@shiro-rs/wasm`をモジュールWorkerで実行し、日本語の単独音（CV）・連続音（VCV）・CVVCの原音設定を推定する。ブラウザとTauriのWebViewで同じ処理を使う。「ツール → 原音設定の自動推定」から開く。

- [shiro-rs](https://github.com/Lqm1/shiro-rs)
- [@shiro-rs/wasm](https://www.npmjs.com/package/@shiro-rs/wasm)
- [仮の日本語モデル](https://github.com/intunist/SHIRO-Models-Japanese)。後でユーザー自身のモデルに差し替える。

## 音響モデルと推定

- shiro-rsと`@shiro-rs/wasm`のライセンスはGPL-3.0-or-later。仮モデルのライセンス表記は見つかっていない。
- 仮モデルはIntunistの`intunist-jp6_generic.hsmm`と`intunist-jp6_phonemap.json`。両方をリビジョン`17694ca5dcfb3ba95ed5ea21fe86b7304d1fafa5`から初回取得し、IndexedDBへ保存する。取得済みならオフラインで使える。モデルはアプリへ同梱しない。
- 別の`.hsmm`とphonemapのJSONをファイル選択で指定できる。指定はダイアログを閉じるまで有効。
- WAVを16kHzへ変換・正規化し、12次元MFCCとΔ・ΔΔの36次元特徴量を5ms刻みで抽出する。前後に無音音素を付け、HMMの粗推定後にHSMMで境界を推定する。
- `@shiro-rs/wasm/bundler`を使い、WASMの読み込みと初期化をViteのESM統合に任せる。Workerの起動完了通知を待って処理を呼び出す。重い処理はWorker内で行う。WAVは1ファイルずつ転送し、キャンセル時はWorkerを終了する。
- 音源別の学習は既定で有効。仮モデルで求めた初期境界とMFCCを使い、HMM・HSMMをそれぞれ3回学習してから全対象WAVを再推定する。反復ごとに進捗を表示する。学習済みモデルはその推定にだけ使い、キャッシュの仮モデルは変更しない。
- 学習ではWAVを保持せず特徴量をWorker内にまとめる。特徴量が256MiBを超えたら対象を減らすよう案内する。少数の録音での学習は精度が下がる場合があるため、学習を無効にして仮モデルで推定することもできる。
- ViteはWorkerとWASMを別アセットとして出力する。開発時はSHIROを依存関係の事前バンドルから除外し、WASMが参照するJavaScriptとインスタンスを共有する。TauriのCSPはWASM実行と仮モデルの取得先を許可する。

## 発音列と生成

- WAV名のひらがな・カタカナを音素列へ変換する。拗音・外来音（すぃ・ずぃ・くぁ／ぐぁ系を含む）・促音・撥音・長音を扱い、読めない文字はエラーにする。音階などの接尾辞は指定して除く。内部の空白・アンダースコアは無音として扱う。
- 生成する「ヴ」のエイリアスはShift_JISで保存できるカタカナ表記を使う。既存の「ゔ」の行を補正する場合は元の表記を保つ。
- フォルダ内または選択した`index.csv`を優先する。形式は`WAV名,空白区切り音素列`。行順を重複エイリアスの優先順とし、標準仮名を音素列から復元する。画面で仮名を指定した場合は音素列との一致を確認する。
- 生成・補正するエイリアスはCV・VCV・CVVCから複数選択できる。推定する音素境界は共有し、共通するCV・VV・語尾の同じ出現は一度だけ生成する。録音内の繰り返しとWAV間の重複は重複上限・連番で扱う。共通のCVはCV、共通のVV・語尾はVCVの設定を優先する。
- 収録BPMは選択WAVのうち5モーラ以上続く最大6録音を仮モデルで解析し、離れたモーラ間の母音開始間隔から推定する。録音ごとの中央値が75%以上一致した場合、推定BPMを最寄りの10 BPMへ丸めて初期入力する。数値の範囲制限は設けない。推定値と使用録音数を表示し、手入力による上書き・再推定・推定値の再適用ができる。手入力は再推定で上書きしない。推定できない場合は、対象録音の不足・発音間隔の不足・録音間の不一致を区別して表示し、初期値120を手入力で変更できる。
- VCVの先行発声は母音境界に置き、収録BPMに応じて先行発声・オーバーラップ・固定範囲・使用区間を設定する。120BPMの連続音はそれぞれ250ms・83.333ms・375ms・583.333ms。音素区間を超えないよう制限する。
- VCVとCVVCで同一母音が連続し、1区間が収録拍の35%未満なら、区間全体の長さが足りる場合だけBPMで分割し直す。補正前後の境界を結果画面に表示する。
- 歌い出しとCVは利用者の`table.csv`の1列目の仮名、5列目の先行発声、6列目のオーバーラップを使う。表なしなら音素境界から求める。表は同梱しない。れんたんさんv0.42の[配布物](https://bowlroll.net/file/102992)はreadmeで改変・再配布を禁止しており、表の例外許可は明記されていない。[連呼採の表](https://tatsu3.hateblo.jp/entry/ar991007)は改変・再配布可能でれんたんさんでも使用できるが、Avennotaの既定の表には採用していない。
- 歌い出しとCVの固定範囲は先行発声の後ろへ100ms取り、使用区間の終わりを超えないよう制限する。
- 無声子音1つと母音からなるCVでは、周期性が明瞭な有声開始が推定された母音境界より10～250ms早い場合、設定の基準点を有声開始に合わせる。音の立ち上がりも検出し、表がなければそこから先行発声を求める。SHIROの音素境界は保持し、補正前後の時刻を結果画面に表示する。有声子音・無声化母音・複数モーラには適用しない。
- CVVCは各モーラのCVに加えてVC・VVを生成する。VCは直前の母音を最大100ms含め、次の母音の開始までを使用し、オーバーラップを先行発声の3分の1にする。VVはVCVと同じ収録BPMの設定を使う。
- VCVとCVVCは最後の母音から無音への遷移を`a R`などの語尾エイリアスにする。内部の無音にも語尾を作り、次の発音へ使用区間を延ばさない。
- 生成は対象WAVの原音設定行を置き換える。重複上限、番号、エイリアス接尾辞を指定でき、番号は接尾辞の前へ付ける。
- 補正はWAVとエイリアスが一致した既存行の数値だけを変える。重複番号も認識し、名前・コメント・行順・未編集行と右ブランクの正負の表現を保つ。

## 結果の反映

推定中は進捗を表示し、キャンセルとエラーでは編集内容を変えない。結果画面で変更行を確認してから反映し、全体を1回のUndoで戻せる。推定後に編集内容が変わっていれば再推定を求める。oto.iniは明示保存するまで更新しない。仮モデルの推定結果は波形と試聴で確認する。

推定が完了しても変更行がなければ、その旨を結果画面に表示し、反映ボタンを無効にする。
